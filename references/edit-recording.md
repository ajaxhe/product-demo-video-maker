# 剪辑用户自录屏（通道 D，默认流程）

目录：1 流程 · 2 先排故事再剪 · 3 剪辑计划 plan.json / edit.json · 4 节奏与时长 · 5 字幕 · 6 推近 focus · 7 打码 blur · 8 多段素材与补录 · 9 验收 · 10 交付与迭代

## 1 流程

```bash
$PY $SK/from_video.py init <项目名> --src <录屏1> <录屏2> ...       # 建项目目录（SKILL.md「项目目录」）；以下 <work> = <ROOT>/<项目名>/work
# 前缀（见 SKILL.md 第 0 步）：cd <work>/_tmp && export TMPDIR=$PWD; 非沙箱运行
$PY $SK/from_video.py analyze <录屏.mov> --work <work>/analyze/<录屏名>   # 每段素材各跑一次：关键帧联系表 + 活动段 runs
# 多段素材：先合成一条时间线（单段素材跳过）
$PY $SK/from_video.py concat <work>/combined.mp4 <录屏1> <录屏2> ...  # → combined.sources.json（每段 offset）
# 写 <work>/plan.json（§3）→ 生成 edit.json + captions_src.srt，打印预计时长与字幕告警
$PY $SK/from_video.py plan <work> --target 30
$PY $SK/from_video.py build <work> --nosub                         # → output/<name>_vN.mp4 + _vN.srt + _vN_无字幕.mp4
$PY $SK/from_video.py reburn <work> [--srt 改过的.srt] --nosub      # 用户只改字幕时
```

- 先确认源文件存在：用户可能中途改名或漏发素材。报 No such file 时 `ls` 目录按大小/修改时间找。找到后复制进项目 `source/`（补发的素材同样），之后只读 `source/` 里的副本。
- 窗口录制不需要 crop；全屏录制才填 `crop`。成片尺寸 = 录屏原尺寸（`out_size: source`）。
- 看不清的段用 `inspect_tool.py frames <录屏> t1 t2 ...` 补抽；要读坐标用 `gridframes`（§6）。

## 2 先排故事再剪（动手前先想清楚）

看完全部关键帧后，先写一张「故事节拍表」，再细剪：

| 节拍 | 典型内容 | 时长占比 |
|---|---|---|
| 入口 | 从上一级页面点进功能（交代"在哪里打开"） | **1–3s，必须有** |
| 操作 | 新建 / 配置 / 输入 / 提交 | 压缩，约 20% |
| 价值 | 结果页、概览、看板、答案、生成物 | **最多，约 40–50%** |
| 细节 | 点开一条看详情、溯源、引用 | 约 20% |
| 落地 | 跳到原文 / 产物 / 下游系统 | 约 10% |

- **入口不能省**：观众要知道功能从哪里进，否则后面的页面看不懂、也学不会。入口段从上一级页面开始（首页 / 设置 / 菜单），每一次点击都推近 + 涟漪，字幕写出路径（§5）；中间的新标签空白页、加载直接剪掉。录屏是直接在功能页里开始的，就请用户补录入口（§10）。
- 每个节拍一条字幕；多段素材按节拍顺序拼，不按文件名顺序。
- 只保留与主题相关的操作：误操作、点了不演示的功能（哪怕 1 秒）、走错页一律剪掉。
- 用户说"××给的时间太长 / 多留时间给××"，就是在调操作与价值的比例：压操作，补价值页。

## 3 剪辑计划 plan.json / edit.json

推荐写 `plan.json`（保留段 + 字幕写在一起，迭代只改这一个文件），`plan` 命令生成 `edit.json` 和 `captions_src.srt`：

```json
{"sources": "combined.sources.json",
 "name": "产品演示",
 "out_dir": "../output",
 "segments": [[1, 9.0, 10.6, 1.2, "第一条字幕"],
              [1, 10.6, 28.4, 25, "第一条字幕"],
              [2, 10.0, 13.6, 0.8, "第二条字幕"]],
 "focus": [{"src": 1, "t": 9.5, "x": 1750, "y": 1190, "zoom": 1.5, "hold": 0.8},
           {"src": 2, "t0": 15.5, "t1": 17.1, "box": [2200, 320, 620, 470], "zoom": 1.7}],
 "blur": [{"src": 1, "t0": 0, "t1": 12, "box": [100, 200, 400, 300], "cell": 26, "note": "说明"}],
 "style": {}}
```

- `segments`：`[源序号, t0, t1, 倍速, 字幕]`，源序号对应 `concat` 输出的 src；单段素材不写 `sources`、改写 `"video": "录屏.mov"`，段写成 `[t0, t1, 倍速, 字幕]`。
- 文字相同的相邻段自动合并成一条字幕（可跨越被剪掉的空档）；字幕写 `""` 表示该段不配字幕。
- 保留段必须按时间递增、不重叠；段与段之间的空隙自动成为 cut。
- `focus` / `blur` 的时间可带 `src`（源内时间），坐标一律源像素；`style` 透传 render.py，缺省自动用微软雅黑。
- `out_dir`：成片输出目录（相对 work），`init` 生成的 plan.json 默认 `../output`；不写则输出到 work 本身。
- `edit.json` 也可手写（字段 `video / crop / cut / speed / focus / blur / style / name / out_dir`，时间=合并片时间），但多段素材、频繁调倍速时用 plan 不易错。
- 用户改了成片 `.srt` 后走 `reburn`；之后若还要改剪辑，先把字幕改动同步回 plan.json，否则再跑 `plan` 会覆盖。
- **plan.json 不支持的两件事**：段间交叉淡化（两页硬切晃眼时用）、红框高亮（标出关键行/列/弹窗）。需要时在项目 `scripts/` 写一个时间线脚本，用 ffmpeg 直接烘出 `work/combined.mp4`：每个保留段 `trim + setpts/倍速 + fps=30`，红框用 `drawbox`（源像素、段内时间 `enable='gte(t,秒)'`，推近时随画面放大），淡化边界分组 concat 后链式 `xfade=transition=fade:duration=0.3~0.7`。同一脚本顺带写出 `captions_src.srt` 与 `edit.json`（时间 = combined 时间，`out_dir: ../output`），再照常 `build`。淡化会让后续时间整体提前 duration，字幕按新时间轴算、相邻两条不要重叠；淡化前后的画面不要推近，否则重影。项目 README 要写明剪辑计划在该脚本而不是 plan.json。

## 4 节奏与时长

**时长预算**：`plan` 打印预计时长；`--target` 偏差 >1s 时告警。
- 超时：先压输入 / 等待 / 加载（表单打字 20–25×，Agent 生成、扫码等待压到 1–3s），再压操作步骤；不压价值页。
- 不够：降低价值页、详情页的倍速（0.8–1.2×），不要为凑时长加新内容或留静止空镜。

**倍速参考**：价值页 0.8–1.0× · 详情/筛选 1.0–1.3× · 勾选/配置 2–3× · 打字 20–25× · 等待/加载 5–8× 或直接剪。核心点击所在段 ≤1.3×，否则推近一闪而过。

**过渡页**
- 开场：入口段 1–3s（§2）。点击处 1×，页面切换的加载剪掉或压 4–7×；直接从结果页开场显得突兀。
- 中段：页面刷新、白屏、加载转圈、空态中间页、新标签打开前的空白 **直接剪掉**，硬切到下一个有内容的画面；高倍速带过的刷新仍会闪，显得多余、画面晃。**入口段尤其多**：点菜单 / 点标签后常有 0.5–5s 转圈或灰色骨架。定边界要用 0.1–0.2s 间隔抽帧：保留到点击后菜单刚收起的那一帧，下一段从内容完整显示的第一帧起（实测一个入口点击后加载 4.8s，只留 0.5s 的转圈帧也会被看出来）。
- **一片演示多个子功能时（如「单篇 → 批量 / 自动」），切换处必须加一条过渡字幕**，例如「不止单篇：还能××」或「下一步：配置批量××任务」，单独占 ≥3s。画面用下一段录屏开头的静止页，放慢到 0.6–0.7 倍，之后再接新功能的入口字幕。直接硬切到下一个入口，观众会以为还在同一个流程里。多出来的时长从操作段和配置段里压。**不要为此单独做一张过渡卡**（用户否过）；设计过的卡片只用在不同功能之间，见 story-cards.md。
- 两个差异很大的页面硬切让人晃眼时，可加 0.4–0.7s 淡入淡出（§8 ffmpeg 技巧）；转场前后不同时推近。
- 有卖点证据的长段（扫码授权、Agent 思考里的关键文字）不要整段剪：先 1× 露出关键帧，再高倍速压等待。

**跨段一致性**：多段/补录拼接时，检查画面里的计数、状态、按钮文字前后是否矛盾（如"检测次数 1"下一镜变成"3"、按钮"执行中"又变回"立即执行"）。选起点避开露出矛盾的区域，或剪掉对应段。**不同时间录的段还要看界面布局是否一致**（侧边栏条目 / 顺序、模型选择器、账号区、版本号）：布局在接缝处突变会让观众以为是两个产品，剪不掉就在交付说明里提示、建议补录。

## 5 字幕

- 每条 ≤20 字、成片里 ≥3s；不够就放慢该段或与相邻字幕合并。
- 入口字幕写路径：「入口：A「B」→ C」（用画面上的菜单原文），覆盖整个入口段。
- 关键步写「动作 + 对象」，其余讲价值（可溯源、权限、自动化、一屏总览）。
- **突出卖点词**：想让观众记住的词（如「一键」「免费」）在字幕里写成 `**一键**` —— 烧入的字幕里这些词变黄色，`.srt` 仍是纯文本，`plan` 告警的字数也不算星号。字幕要突出时只染词，不放大整条、不加图标；每条最多染 2 个词。
- 有过渡页（story-cards.md）的片子，字幕不再写「第 N 步」：页面上的章节编号已经是步骤序号，两套编号并存会对不上。
- **只写画面里看得见的**：不下画面证明不了的判断（"短板一眼可见"；"更准 / 更好"需要有对比画面才能写）；数字、时间、名称以画面为准，不照搬脚本或口头描述。
- **不解读 sample 数据**：演示的是产品能力，不写"达成 xx%、根因 xx"之类的数据结论。
- 流式输出的文字（Agent 回答、摘要）按**文字实际出现时刻**对位，逐 0.5s 抽帧确认。
- 字体微软雅黑：`/Applications/Microsoft Word.app/Contents/Resources/DFonts/msyh.ttc` + `msyhbd.ttc`（`msyh.ttc` 的 index 1 是 YaHei UI，不是粗体）。字幕已按「国」字墨迹垂直居中，不要再加偏移。

## 6 推近 focus（用户录屏没有点击数据，必须手工补）

**读坐标**：`$PY $SK/inspect_tool.py gridframes <源录屏> t1 t2 ... --out-dir <work>` → 每帧一张图，网格标签就是**源像素**，直接读标签填 focus，不用换算。Read/ViewImage 显示的图会缩放，千万别读显示像素。点击时刻取活动段起点，抽「点击前 0.1s」的帧（光标还停在目标上）。

**推什么**
- 只推核心点击（**入口路径上的每一次点击**、新建、提交、关键选项、打开详情、跳转）和局部小组件（弹窗、侧边面板、图表中的一块、标签区）。
- 横跨整屏的元素（整行数据卡、整行图表、全宽表格）**不推**：推近只会把两侧裁掉。
- 倍数：点击 1.4–1.6，区域 1.3–1.8。box 推近会按 0.8×屏宽/屏高自动限幅，限幅后 <1.15 则不推。
- **连续点击要「保持推近」，别拉远再推近**：同一个小区域里先后点两次（如「更多」→ 弹出菜单里的某项），第一次点击的 `hold` 取到下一次点击的时刻（`hold ≈ 下次点击时间 − 本次点击时间 + 0.05`，源时间），镜头就会一直保持放大并平移过去；`hold` 太短会在两次点击之间拉远又推近，短时间 zoom out / zoom in 很晃（用户反馈过）。该段的倍速别太快，否则这段镜头太短。
- **弹窗 / 详情面板**：只推「触发它的那一次点击」（如点卡片），弹窗一出现就回到全景；不要再对弹窗里的按钮（去试试 / 确定）推近——放大后弹窗会被裁掉一半。触发点击的 `hold` 取 0.1–0.2s，让镜头在弹窗出现前就开始拉回。

**镜头要连贯（推近宁少勿多）**
- 几秒内多次推近会"放大—缩小—放大"来回晃。同一屏内连续关注的点：一次推近 + 平移过去（前一个的 t1 接上后一个的 t0，间隔 <1.2s 自动平移不拉远）。
- 只为"点了一下"而推近的可以删掉，保留能让观众看清结果的那一次。

## 7 打码 blur（对外视频必做全片检查）

- blur 作用在推近之前的源帧上，镜头放大后马赛克依然覆盖。
- **用户只框了一处时也要全片扫**：同类信息常在别处再出现（侧栏团队列表、上传/选择目标弹窗里还有一份）。
- 必查清单：知识库/团队列表（只保留演示用的）、上传/选择目标弹窗、快速访问/最近访问、人名、全屏水印、未发布的模型名、通知弹窗、浏览器地址栏里的内部 ID。拿不准的列出来问用户。
- 列表排序会变（补录与主录进入顺序不同），每段单独定 box；保留项夹在中间时拆成上下两块。
- 渲染后**原分辨率裁剪放大**核对（缩略图看不出漏打/误挡）。

## 8 多段素材与补录

- **多段录屏 / 漏发的素材**：先复制进 `source/`，再 `concat` 统一处理（各段先归一 30fps 再无损拼接，offset 按帧数算，避免 60fps 素材半帧误差）。用户补发素材时按故事节拍放进正确位置重新 `concat`，plan.json 里改源序号即可，各段内的 focus/字幕时间不用重算。
- 各段分辨率必须一致（同一窗口尺寸录制），不一致 `concat` 直接报错。
- **给已定稿的项目在前面（或中间）加一段新素材**（如补「开通 / 配置」入口段）：不要重写 plan。把现有合并片改名 `combined_base.mp4`，`concat` 出新的 `combined.mp4` = 新素材（src 1）+ combined_base（src 2）；旧 plan.json 的每个保留段 / focus / blur 都加 `src: 2`，**时间一律不动**（src 内时间不受前面新增段影响）；新段用 `src: 1` 的源内时间写。旧 plan 先备份到 `work/history/`；项目 `scripts/make_combined.sh` 同步改成两步，README 写明各 src 对应什么。字幕步骤序号（第 N 步）顺延，别留重号。
- **插入一段补录到主录中间**（同一页面状态接续）：

```bash
ffmpeg -i main.mov -i supp.mov -filter_complex \
 "[0:v]trim=0:6,setpts=PTS-STARTPTS,fps=30[a];[1:v]setpts=PTS-STARTPTS,fps=30[b];\
  [0:v]trim=start=6,setpts=PTS-STARTPTS,fps=30[c];[a][b][c]concat=n=3:v=1[v]" \
 -map "[v]" -c:v libx264 -preset ultrafast -crf 14 -pix_fmt yuv420p combined.mp4
```
  时间映射：主录 `m(t)= t if t<插入点 else t+补录时长`，补录 `s(t)= t+插入点`。插入点选在画面状态与补录开头一致处，并替换掉主录里讲同一件事的段。

**ffmpeg 烘焙技巧**（render.py 没有的效果，在生成合并片时加）
- 红框高亮某个 UI 区域：对应段 `setpts` 之后加 `drawbox=x:y:w:h:color=red@0.95:t=9:enable='gte(t,段内秒)'`（源像素），推近时红框随画面放大不会错位。
- 页面间淡入淡出：每段先 `fps=30,format=yuv420p,settb=AVTB`，再链式 `xfade=transition=fade:duration=0.5:offset=前段累计长度-0.5`；xfade 让后续时间整体提前 duration，字幕与 focus 时间要按新时间轴重算。

## 9 验收（交付前必做；看不到视频，靠抽帧）

`$PY $SK/inspect_tool.py frames <成片.mp4> t1 t2 ...`（输出自动编号，不覆盖旧图）：
- 开场入口：前 3s 每 0.3s 抽一帧，入口菜单文字推近后可读，没有空白页 / 加载帧。
- 每条字幕中点：字幕与画面对应、无错别字、写的都是画面里看得见的。
- 每个推近 +0.15s：已推近到目标，目标完整未被裁，涟漪在目标上。
- **镜头连续性**：推近密集段每 0.5s 抽一帧，相邻帧不应出现放大→缩小→再放大。
- **无多余画面**：中段没有白屏、刷新、加载转圈、空态中间页；没有与主题无关的操作。
- **跨段一致**：计数、状态、按钮文字前后不矛盾。
- 打码段原尺寸裁剪核对；时长达标；每条字幕 ≥3s。

## 10 交付与迭代

- 每次给三件：`_vN.mp4`（字幕烧入）、`_vN.srt`（可改）、`_vN_无字幕.mp4`（剪映用：导入字幕 → 选一条设样式 → 应用到全部），都在项目 `output/`，版本号只增不覆盖。
- 交付前更新项目 `README.md`（当前版本、待确认/待补录）和 `CHANGELOG.md`（本版：用户反馈 → 改动）；项目专用脚本放 `scripts/`。
- 回复里写清：时长、字幕条数、按节拍的画面/字幕表、推近/打码处理了哪些、剪掉了什么及原因。
- 主动指出**素材缺口**：缺入口（录屏直接从功能页开始）、想表达但没拍到的（如配置了 4 项只演了 1 项、想讲"效果更好"却没有对比录屏），建议补录什么。
- 对外视频提醒：浏览器顶栏（标签页、含内部 ID 的地址栏、"有新版浏览器"提示）是否裁掉，由用户决定后再加 `crop`。
- 用户改 srt（文字或时间）→ `reburn`；改剪辑/推近/打码 → 改 plan.json（或 edit.json）后 `plan` + `build`。
