# 故事线合集与故事卡（按参考 PPT 的视觉做过渡页）

把多个功能演示片串成一条有客户故事线的片子（展区循环播放、发布会暖场），功能之间插入「故事卡」。
本文的「故事卡」是**设计过的过渡画面**（开场 / 章节 / 结尾）。edit-recording.md §4 里的「过渡页」指录屏里的加载页、白屏，那些要剪掉，两者不是一回事。

目录：1 什么时候加故事卡 · 2 视觉从 PPT 来 · 3 故事线怎么编 · 4 流程与命令 · 5 卡片版式与文案 · 6 拼接、转场、字幕 · 7 验收 · 8 交付

## 1 什么时候加故事卡

默认不加（SKILL.md「默认偏好」）。满足下列**任意一条**才加：

- 用户明确要片头、片尾、过渡页、章节页。
- 一条片子里串了**几个不同的功能**（各有入口、各讲一个价值），只靠字幕切换，观众分不清哪里换了话题。

只放在**不同功能之间**，以及开场、结尾。**同一功能内部**的子步骤切换（如「单篇翻译 → 批量翻译」）不加卡，用「过渡镜头 + 过渡字幕」交代（edit-recording.md §4）。用户明确否过「章内单独做一页」的方案。

## 2 视觉从 PPT 来（有参考 PPT 时必须这样做）

用户给了同一场合的 PPT（演讲稿、发布会稿、大会模板），并且视频和这份 PPT 是**同一个场景下用**（同一场大会、同一个发布、同一个展区），故事卡就直接取 PPT 的视觉规范。不要自己另配一套背景，也不要用 render.py 内置的 intro/outro 主题。这样视频放在演讲旁边播放，看起来是一套东西。

- **取什么**：版式（slideLayout）里的整页底图（封面图、内容页图）、大会或品牌 logo（透明 PNG）、标题字体和正文字体、主色和渐变色。
- **怎么取**：`story.py ppt <deck.pptx> --out <项目>/assets/ppt`，会输出：
  - `_media_sheet.jpg`：全部底图和 logo 的联系表，灰底，透明 logo 也看得见。用 ViewImage 看，挑出封面底图、章节底图和 logo。
  - 版式使用次数：第 1 页用的版式≈封面，用得最多的≈内容页。
  - 字体排行，并标出本机有没有这个字体。
  - `_outline.md`：每页全文和演讲备注。故事线和金句从这里取（§3）。
- **怎么用**：
  - 开场卡、结尾卡用封面底图 + logo。
  - 章节卡用内容页底图，或画面干净、有一条色带的那张。
  - 标题和正文用 PPT 里排名靠前、本机也有的字体。本机没有就用微软雅黑，并在交付时说明。
  - 渐变色、强调色从底图里取。
  - 字幕仍用微软雅黑粗体，和各子片保持一致。
- **PPT 在资料库或乐享上**：先下载到本地再拆。用户给的是 `workbuddy.cn/space/d/<nodeId>` 链接时，**不要 WebFetch**（返回登录页，拿不到内容）：用资料库 skill 的 `space_api.py space.workspace.node-info --node-id <id>` 看类型，`kind=drive` 且 `ext=pptx` 就 `drive/get_download_link.py --node-id <id>` 取短期下载链接，立即 `curl -L` 存到项目 `work/ppt_ref/`。乐享走文件下载。
- **同一场合的其他项目已经拆过这份 PPT**：先看 `~/Movies/demo-videos/` 里同场合项目的 `assets/`，对照 md5 复用底图和 logo，不要另配一套。
- **没有 PPT 但要加卡**：问用户要大会或品牌 KV。实在没有，再用 `assets/style_summit_dark.json` 的深色主题，并在交付时说明。

## 3 故事线怎么编

- **主旨对齐演讲**：从 `_outline.md` 里找能力分层（如「连接 / 索引 / 治理」）、要解决的问题、金句。章节卡标题写成「能力层 · 功能名」，结尾卡用演讲的主标题和金句。
- **客户故事匿名**：先检索知识库里的行业和客户案例，找真实痛点。片中写「某××品牌 · ××部门（演示使用模拟数据）」，**不出现客户名称、客户细节、客户数据**。
- **开场卡讲冲突**：一句具体场景，再加一个问题，例如「新品上市第一周，售后知识跟得上吗？」。下方用流程标签预告各章。
- **每张章节卡三行**：
  - 编号 + 标题；
  - 一句故事：这一章在客户故事里解决什么，用画面里会出现的实体名；
  - 价值标签：**只写价值短语**，不加「解决」之类的前缀。
- **子片字幕改写成故事语境**：如「勾选整批文档」改成「勾选整批新品资料」。仍然只写画面里看得见的内容（edit-recording.md §5）。
- **时长分配**（以 2 分钟为例）：开场 5s，每张章节卡 3–3.5s，结尾 4–5s，其余平均分给各章录屏。章节卡太长会显得拖。

## 3b 在单个项目内加过渡页（一片就是一个项目，按功能切章）

用户要在一条演示片的几个功能之间加过渡页，而不是把几个子项目串成合集时，不用新建故事线项目：把**本项目自己**当成唯一的章节素材，卡片插在章节交界处。

- `story.json` 里 `"chapters": {"main": {"project": "."}}`，`story.py chapters` 读本项目 `work/edit.json` 渲出无字幕、含推近/打码的 `work/chapters/main.mp4`（时间 = 无卡成片时间）。
- 时间线把 `main` 切成几段（按功能交界切），段与段之间放 `{"card": ...}`；每段的 `caps` 取自 `captions_src.srt` 换算到 `main` 时间。在项目 `scripts/make_story.py` 里由 plan.json 自动生成，避免手算（改了 plan 就重跑）。
- `size` 取录屏原尺寸（如 `[3024, 1878]`），卡片按 1920 宽等比放大；不用裁成 16:9。
- 卡的数量：默认「每章一张章节卡（含第一章）」，用户明确说过「功能之间」且没提第一章时，先只放功能交界；用户补一句「开头要总说明 / 01 少了」就补**开场总览卡**（cover：PPT 封面底图 + logo，大标题用演讲主题，flow 标签与章节一一对应）和第一章的章节卡。结尾卡仍要用户提才加。开场卡 4.5s、章节卡 3.0s，淡化 0.5s，每张净增约 2.5s（开场卡约 4s）。
- 加卡会把紧邻的字幕淡化掉 0.5s：首章第一条字幕、每章最后一条字幕要留够 3.0s + 0.5s，`story.py plan` 看 `<3s` 告警，放慢对应保留段后重渲章节。
- 章节名写成「能力层 · 功能名」，并对到演讲的能力分层；本片内容跨层或不属于任一层时，在交付里列出让用户确认。
- 出片后字幕要改：`story.py` 没有 `reburn`，改 `plan.json` 的字幕（或让用户改 `.srt` 后由你同步回 plan.json），重跑 `plan` → `make_story.py` → `chapters` → `build`。

## 4 流程与命令

```bash
# 前缀：cd <项目>/work/_tmp && export TMPDIR=$PWD; 非沙箱
$PY $SK/from_video.py init <场景>_故事线 --src <各子片定稿无字幕版...>   # 建项目；source/ 只作参考归档
$PY $SK/story.py ppt <deck.pptx> --out <项目>/assets/ppt              # §2
# 写 <work>/story.json（模板 assets/story_example.json）：fonts / card_theme / crop / chapters / cards / timeline
$PY $SK/story.py chapters <work>          # 子项目 edit.json → work/chapters/<key>.mp4（无字幕、裁切后的章节素材）
$PY $SK/story.py cards <work>             # 故事卡末帧 → work/checks/card_*.jpg，先看卡再出片
$PY $SK/story.py plan <work>              # 时间线、字幕表、总时长、<3s / >20 字告警
$PY $SK/story.py build <work>             # → output/<name>_vN.mp4 + _vN.srt + _vN_无字幕.mp4（2 分钟约 1–4 分钟，后台跑）
```

- **章节素材要重渲，不能拿子片成片来裁**。子片成片带浏览器顶栏，而展区屏幕是 16:9。裁切必须在推近之前做，`chapters` 会把 crop 交给 render.py，推近坐标会跟着平移。直接裁成片会把推近画面的顶部内容裁掉。crop 取浏览器顶栏下沿的 y 坐标（按源像素逐行扫颜色突变来定），高度取 `宽 × 9/16`。
- 子项目改了剪辑：先重跑 `chapters <work> <key>`，再 `build`。
- `timeline` 条目：
  - `{"card": key, "xf": 淡化秒}`
  - `{"clip": [章节key, t0, t1, 倍速], "xf": 秒, "caps": [[t0, t1, 字幕], ...]}`
  - 时间都是**章节素材内**的时间，也就是子项目定稿成片里的时间，可以直接对照子项目的 srt。
- 不支持的版式或效果：在项目 `scripts/` 里复制一份 story.py 改，并在 README 写明。

## 5 卡片版式与文案

| layout | 用途 | 字段 |
|---|---|---|
| `cover` | 开场 | `bg logo kicker title[] sub flow[]` |
| `chapter` | 章节 | `bg no title story tag` |
| `end` | 结尾 | `bg logo kicker title[] sub pillars[[名,一句价值]]` |

- 文字统一左对齐，放在底图的暗区，不压色带或高光（用 `cards` 出的静图检查）。
- 动效：背景 5% 缓慢推近，文字逐行上滑淡入（0.45s，间隔 0.15s）。不做花哨转场。
- 字号（1920 宽基准）：标题 84–112，故事句 42–44，标签 30。故事句 ≤ 30 字，一行放下。
- 结尾卡的 pillars 和章节一一对应。如果有一章不属于演讲的能力分层（如「服务全球 · 智能翻译」），交付时问用户是并列写，还是写成「三层能力 + ×××」。

## 6 拼接、转场、字幕

- **转场**：卡和录屏之间交叉淡化 0.5s；同一章内录屏段之间 0.3s；连续片段内部倍速分段用 0（无缝）。
- **字幕不压在故事卡上**：从卡淡入的片段，字幕等淡化结束再出；后面接卡的片段，字幕在卡开始淡入前收掉（story.py 已自动处理）。被截短的字幕要回到 `plan` 看是否 <3s，不够就把所在片段放慢到 0.8–0.85×。
- **每条字幕单独成段**，便于逐条调倍速：一个片段里有多条字幕时，要放慢其中一条，就把片段从字幕边界拆开（`xf: 0`）。
- **凑时长**：先缩卡（开场 5.6→5.2、章节 3.4→3.2、结尾 5.6→4.2），再给操作段、配置段提速（1.3–1.5×），最后才动价值页。
- **剪掉的内容**：子片里为单片自洽而加的段（单片的过渡字幕段、和故事线无关的设置页、重复的结果展示），在合集里可以剪。交付时列出剪了什么。

## 7 验收

- `cards` 静图：文字不压底图色带或高光，行与行不挤，logo 清晰，标签里没有多余前缀。
- 成片抽帧（`inspect_tool.py frames`）：每张卡中段、卡前后 ±0.3s 的淡化帧、每条字幕中点。
  - 字幕框不出现在深色卡或淡化帧上；
  - 没有浏览器顶栏；
  - 没有黑边（16:9 裁切到位）；
  - 淡化帧里没有推近重影。
- 总时长和目标相差 ≤1s，每条字幕 ≥3s。

## 8 交付

- 三件：`_vN.mp4`、`_vN.srt`、`_vN_无字幕.mp4`。说清楚两个视频的区别：只差字幕是否烧入，故事卡上的字两版都有。
- README 写清：
  - 故事线（客户原型只写在 README，不进片子）、各章来自哪个子项目的哪个版本；
  - 节拍表；
  - 怎么改：`story.json` 的 cards / timeline。
- 待确认项：
  - 客户匿名写法、「模拟数据」标注是否保留；
  - 结尾能力并列方式；
  - 子片遗留的打码问题（账号名、水印）；
  - 是否加 BGM。展区循环一般静音。
